# 주간 통합보고 지표 연결

화면·PDF·HTML·Excel(한 시트)은 0~6번 양식을 공통 사용합니다. 지표를 불러오지 않으면 자료 미확인으로 표시하며 직접 집계값도 입력할 수 있습니다. 입력·조회 값은 생성 시 스냅샷에 보관하므로 과거 문서를 다시 다운로드할 때 재조회하지 않습니다.

## 1. 공용 저장 활성화

Supabase SQL Editor에서 [supabase/weekly-summary.sql](../supabase/weekly-summary.sql)을 실행합니다. 기존 보고·계정·문서는 삭제하지 않습니다. 새 RPC는 인증된 팀원만 호출하고 기존 서버 문서 생성 함수로 보고를 조회합니다. 설정 전에는 지표 없는 문서를 기존 방식으로 저장할 수 있으며 지표 포함 PDF·Excel·HTML은 개인 다운로드만 가능합니다. 지표 포함 저장 시 설정 안내를 표시하며 저장 성공으로 안내하지 않습니다.

## 2. 세미나 및 현재 주 신규 회원 자동 연결

기존 회원 대시보드 Apps Script 프로젝트에 [apps-script/weekly-report-extension.gs](../apps-script/weekly-report-extension.gs)를 추가합니다. 기존 Code.gs doPost의 비밀번호 확인 성공 이후 try 블록 맨 앞에 다음 한 줄을 추가합니다.

```javascript
if (req.action === 'weeklyReport') return json_(weeklyReportMetrics_(String(req.weekStart || '')));
```

배포 관리에서 기존 웹 앱을 새 버전으로 갱신해 URL을 유지합니다. 배포 계정에 회원분석, 활동성, 세미나 원본 열람 권한이 필요합니다. 원본은 수정하지 않으며 회원 가입일은 시트 안에서 집계합니다. 원본 개인 행은 반환하지 않습니다. 앱의 ‘주요 지표 연결 및 집계값 입력’에서 대시보드 비밀번호를 입력하고 ‘원본 지표 불러오기’를 선택합니다. 비밀번호는 DB·localStorage·소스에 저장하지 않습니다.

확장 전에도 기존 활동성 API와 완료 주간 회원 집계, 암호화된 포인트 월 집계를 이용할 수 있습니다. 세미나·현재 주 회원 값이 없으면 미확인으로 표시하고 수동 입력할 수 있습니다.

## 집계 기준

- 기간은 월~일이며 금요일 제출 마감과 구분합니다.
- 회원 신규는 가입일 기준입니다. 탈퇴 데이터가 없으므로 순증감을 추정하지 않습니다.
- 활동성은 해당 주 전체 기기 행만 사용합니다. 중복 행은 마지막 행을 사용하고 PC/MO·페이지별 고유 사용자 수를 합산하지 않습니다.
- 세미나는 raw D:O에서 일자·완료·신청·시청·만족도·유용도를 확인합니다. 신청·시청은 완료 세미나 참여 건수 합계, 만족도·유용도는 기입된 점수의 단순 평균입니다.
- 포인트 원본은 월별입니다. 선택한 주 시작일이 속한 월의 공개 집계를 표시하고 실제 월 집계 기간을 명시합니다. 주간 지급·사용 값으로 표시하지 않습니다. 잔여 포인트는 원본의 기초 잔액 가정·제외 규칙을 따릅니다.
- 미확인과 0을 구분합니다. 직접 입력값은 지표명 | 값 | 단위 | 전주 값 형식이며 집계 기간·근거를 함께 입력합니다.

## 검증 범위

Node 테스트에서 기간 경계·중복 활동성·빈 점수·포인트 월 구분·출력 섹션 및 HTML 이스케이프를 검증합니다. 실제 Apps Script 재배포·Supabase RPC 적용·브라우저 파일 다운로드는 해당 계정의 서버 설정 적용 이후 확인이 필요합니다.
